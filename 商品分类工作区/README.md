# 商品自动分类项目（中国站 / 全站点复用）

把商品信息表，按 **中国站真实分类树** 自动填好 `产品分类 / 二级分类 / 三级分类` 三列。
输出结果里**每一个三级类都保证存在于中国站分类树中**，匹配不到的诚实标 `待确认`，绝不编造。

> **站点复用于 cn / es / gr 全站点**：西班牙站、希腊站的上传模板分类列即为**中国站中文三级分类**。
> `一键全流程.bat` / `货号匹配-选站生成.bat` 均已把本分类引擎（含人工核对/填回闭环）接入三个站点，
> 分类树、主数据库、规则三站共享，无需为 es/gr 另建分类体系。

## 二、怎么用（3 步）

**前提**：电脑里这个 Python 能用（由根目录 uv 环境提供）：
```
product-data-toolkit\.venv\Scripts\python.exe
```
（首次使用请先在本项目根目录执行 `uv sync` 生成 .venv；详见根 README 第〇节。）

**第 1 步**：把要分类的商品表（.xlsx）放进 `input/` 文件夹。
- 表里有 `品名 / 货号 / 条形码` 这三列即可（**表头名称不固定**，程序自动识别，列顺序无所谓）。
  支持各种异名表头，例如 `商品名/货物名称/title`、`货物编码/SKU码/款号/型号`、`条码/国际条码/EAN`、
  `一级类目/类目/品类`、`二级类目`、`三级类目` 等；识别不到的列只跳过对应匹配层，不会报错。
  工作表名也不固定，自动取第一个有数据的表（兼容中文表名如 `匹配结果`）。
- **两种“已有分类”的处理方式（严格优先）**：
  - 表头是纯净的 `产品分类 / 二级分类 / 三级分类` → 视为【最终分类】：原列**原样保留、绝不被覆盖**，
    只在末尾追加一列「系统复核」（`有效`=整链在标准树内 / `待确认`=不在标准树整链）。
  - 表头是 `原产品分类 / 原二级分类 / 原三级分类`（`原`开头，旧参考列）→ 视为【参考列】，
    **不当最终分类**，仍按主库/品名/关键词重新分类，并在末尾追加 `产品分类/二级/三级` 三列。
  - 完全没有分类列（仅品名/货号）→ 直接重算并追加三列。
- **新建 sheet「程序推荐分类」**：程序用主库/规则算出**推荐的一到三级分类**，
  写进新建的 `程序推荐分类` 工作表（列：品名、货号、推荐产品分类、推荐二级分类、推荐三级分类），
  与原表主数据分开，方便你对比原分类与推荐值、按需采用。
  - **规则：原表分类已通过校验（系统复核=有效）的商品不再写入推荐 sheet**——它们无需重新推荐；
    只有原表未通过校验（待确认）或原表无最终分类列（重算模式）的商品才进入推荐 sheet。
  - **主表「四级分类」列**：原表【未通过校验】(待确认)的商品统一填「待确认」；
    原表**复核有效**的商品不填待确认——保留原表四级值，原表为空则留空。
- 运行时会先打印一张「表头自动识别」对照表，一眼确认每列认对了没；若某列没认到会提示。

**第 2 步**：双击或在终端运行：
```
cd <clone 目录>\商品分类工作区
..\.venv\Scripts\python.exe classify.py
```
（也可以指定文件：`..\.venv\Scripts\python.exe classify.py 路径/你的表.xlsx`）

**第 3 步**：去 `output/` 拿结果。结果文件在原名后加 `_已分类`，
新增三列 `产品分类 / 二级分类 / 三级分类`，原数据一字不删。

## 三、分类逻辑（四层，按你定的优先级，从高到低）

1. **① 货号精确匹配**：用 `货号` 去 17 万主数据库里查，有 → 直接采用主数据库分类（最权威）。
2. **② 品名相似匹配**：货号没有，则用商品名称里的"核心词"去主数据库找
   **品名包含该核心词**的商品，借鉴其分类（多数投票 + 整体相似度过滤，避免歧义借错）。
   *结合原表分类*：若原表已明确归为"玩具"，则不被厨房/家居等日用品借走；
   强字面关键词（线/发箍/抓夹/发夹/耳环…）已明确，交给③，不走②。
3. **③ 字面 + 原分类理解**：主数据库也无，则按品名字面意思 + 原分类归类：
   - 原表旧分类若本身在中国站树内 → 保留；
   - 否则按关键词规则兜底（例：带"抓夹"→发饰系列/抓夹系列；带"过家家"→玩具系列/儿童玩具/DIY玩具；
     带"毛线"→家居百货/缝纫针线系列/针线组合），规则按"原一级"分组启用防跨类误判；
   - 全国站有、中国站无的叶子 → 就近归并（例：家纺系列/枕头 → 抱枕芯）。
4. **④ 无法确定**：以上都不行 → 标 `待确认`，**不编造任何类目**。

> 所有结果都经过一道**校验**：写出的每一行三级类，都会再去中国站树里查一遍，
> 不存在就降级成"待确认"。所以你拿到的文件里**不会有任何一个编造的类目**。

## 三之二、为什么还有"待确认"

待确认 = 中国站分类树里**确实没有对应叶子**的商品（如跳舞毯、伸缩龙、独特玩具等），
或主数据库与树都查不到相似项。这类不是程序错，而是**分类树需要补充**这些细类。
后重跑即可自动归；或人工确认后回填。

## 四、怎么维护规则（新增/修改分类词）

分类词都集中在 `rules/` 里，改这里就行，**不用动 classify.py**：

- `rules/rules.py` —— 玩具、发饰（儿童系列）、母婴 的规则。
- `rules/rules_full.py` —— 厨房、家居、饰品、宠物、电器、节日、户外、箱包 的规则。

每条规则写法都是：`(关键词, 一级, 二级, 三级)` 或 `(关键词, 二级, 三级)`（玩具类一级固定"玩具系列"）。

**例：想让"积木"归到 玩具系列/儿童玩具/益智玩具**
在 `rules/rules.py` 的 `TOY_RULES` 里加一行：
```python
('积木','儿童玩具','益智玩具'),
```
保存后重新跑 `classify.py` 即可。

> 提示：不确定三级类叫什么名字时，打开 `data/中国站商品分类.xlsx` 的
> `Sheet1`，按 `产品分类 / 二级分类 / 三级分类` 三列查找真实名称。
> 程序加载时会自动过滤掉"中国站树里不存在"的规则并打印提示，写错也不会出错。

## 五、重要约定（请牢记）

- **中国站才是校验标准**。全国站（`产品分类cn&es.xlsx`）比中国站多 6 个一级类、
  568 个三级链，不能用来兜底，否则会把商品分到中国站根本不卖的类目。
- 换站点时：把对应的分类树放进 `data/`，改 `classify.py` 顶部 `CN_TREE` 常量即可。
  （当前 cn / es / gr 三站统一复用 `data/中国站商品分类.xlsx`，无需修改。）
- 主数据库（`master/`）是公司商品真相来源；如果数据库更新了，直接替换该文件。

## 七、优化记录（2026-08-21）

针对实际使用中发现的两个问题做了三处优化（原文件备份在 `classify.py.bak`）：

1. **确定性修复（重要）**
   - 原因：`similarity_match` 的平局取法（`vote.most_common(1)`）和 `normalize_to_tree` 从 set 取首个元素，
     都依赖集合迭代序，而 Python 字符串哈希每进程随机 → **同一输入两次运行结果可能不同**。
   - 修复：平局按 `(票数, 一级, 二级, 三级)` 字典序取最大；所有 set 迭代前 `sorted()`。
   - 验证：同一源表连续跑两次，1335 行 × 9 列逐格对比 **0 差异**。

2. **"茶水杯"误借修复**
   - 原因：相似度用整串 LCS，"茶水杯200ml" 与 "保鲜盒200ml" 因共享 "200ml" 而被借到保鲜盒，
     容量数字主导了匹配，而非品类词"杯"。
   - 修复："茶水杯"加入强字面关键词（跳过品名相似层），并加入精确规则 →
     `茶水杯 → 厨房用品/饮具系列/陶瓷杯`。

3. **normalize 对齐逻辑修正**
   - 原因：`normalize_to_tree` 无条件执行，导致规则明确指定的
     `厨房用品/饮具系列/陶瓷杯`（本身就在中国站树内）被按字典序"对齐"成 `陶瓷制品/陶瓷杯`。
   - 修复：**已在中国站树内的分类不再对齐**，保留规则/主数据库指定的二级；仅树外的链才做对齐兜底。

最新成果（input/商品信息分类_源表.xlsx，1335 商品）：
- ① 货号精确=344 | ② 品名相似=130 | ③ 字面/原分类=822 | ④ 待确认=39
- 已归类 1296、待确认 39、**无效链 0**；两次运行结果逐格一致。

## 八、优化记录（2026-08-25）

针对拖拽运行异名表时暴露的两类问题做了修复（旧文件备份在 `classify.py.bak2`）：

1. **表头/工作表名不再写死（自动识别）**
   - 原因：原 `locate_columns()` 用固定别名清单，表头叫 `商品名/货物编码/一级类目` 就认不到、丢列；
     且 `ws['Sheet1']` 写死，中文表名（如 `匹配结果`）直接 `KeyError` 报错。
   - 修复：表头改为「精确别名 + 关键词模糊」双层匹配（见 `xlsx-header-automap` skill）；
     新增 `first_sheet()` 自动取第一个有数据的表。运行时打印「表头自动识别」对照表。
   - 验证：6 组异名表头（中文变体/英文/带多余列）全部正确映射。

2. **原表分类“严格优先”处理，杜绝误覆盖**
   - 现象：拖入的 `货号匹配结果.xlsx` 本就有 `产品分类/二级/三级`，却被 ①货号匹配主库后**整列覆盖改写**
     （原 `卫浴用品/…` 被改成主库的 `家居卫浴/卫浴用品色系套装/白色系列`），且因 normalize 对齐，
     整链不在树内也被误判“有效”。
   - 修复（按用户定的方向，两层判断）：
     - 表头是纯净 `产品分类/二级分类/三级分类` → 视为【最终分类】：原列**原样保留、绝不被覆盖**，
       仅追加「系统复核」列（有效=整链在标准树内 / 待确认=不在）；此模式下**不跑**匹配层、**不**做 normalize 对齐。
     - 表头是 `原产品分类/原二级/原三级`（`原`开头参考列）→ 视为【参考列】，不当最终分类，
       仍走完整四层重算、末尾追加三列。
     - 完全无分类列 → 直接重算追加三列。
   - 验证：
     - `货号匹配结果.xlsx`（纯净列）→ 原列 0 行改动，系统复核 20 条全待确认。
     - `input/商品信息分类_源表.xlsx`（原列）→ 恢复历史成果 已归类1296 / 待确认39 / 无效链0。
     - 4 种边界表头（纯净有效/纯净无效/原列/无列）均行为正确、无报错。
